技术选型｜C++与SDL2

技术选型是我们今天讨论最久的话题。候选方案有三个：SDL2、SFML、Unity。

  • Unity：开发效率高，但我们是课程设计，希望深入理解游戏引擎底层原理，且 Unity 对 Linux 支持一般；
  • SFML：封装更友好，文档好，但依赖较新，在课程环境里装机成本高；
  • SDL2：轻量、跨平台、C/C++ 原生接口，能直接操作渲染/输入/音频底层，最适合我们”从零实现游戏引擎核心”的目标。

最终确定：C++17 + SDL2 + SDL_image + SDL_mixer + SDL_ttf，构建用 CMake。虽然开发量比 Unity 大，但能真正学到渲染管线、事件循环、资源管理的本质，对后面求职也更有说服力。

我把选型结论和理由写进了技术文档，并标注了每个依赖库的版本号，防止环境不一致。

踩坑与解决
依赖版本不一致：成员机器 SDL 版本不同，行为不一样。解决：统一版本并锁定（SDL2 2.0.22 + SDL_image 2.0.5 + SDL_mixer 2.0.4 + SDL_ttf 2.0.18）。选型纠结：Unity vs SDL2 争论。解决：以”学习引擎原理 + 课程设计”为目标选 SDL2，理由写入文档。SDL_image 初始化失败：只初始化了 SDL 没初始化扩展库。解决：IMG_Init/TTF_Init/Mix_OpenAudio 都要显式调用。
